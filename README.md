# ЇжРозумно 🥗

PWA-застосунок для обліку спожитих калорій, ведення щоденника харчування, контролю ваги та перегляду статистики у зручному mobile-first форматі.

**Мова інтерфейсу:** українська

---

## 🎯 Мета продукту

Користувач повинен мати змогу:

- фіксувати спожиту їжу протягом дня
- переглядати загальну кількість калорій за день
- аналізувати динаміку по днях, тижнях і місяцях
- контролювати вагу та прогрес до цілі
- швидко знаходити або створювати продукти
- експортувати власні дані
- переглядати історію ваги

## 📱 Формат продукту

На першому етапі застосунок розрахований на персональне використання одним користувачем. Архітектура має враховувати можливість подальшого розширення до багатокористувацького сценарію.

---

## 📖 Основна концепція

У застосунку є дві основні сутності:

- **Продукт** — довідникова одиниця з назвою, фото, виробником і харчовими характеристиками
- **Запис їжі** — факт споживання конкретного продукту в конкретний день і, за потреби, у межах конкретної категорії прийому їжі

---

## 🧩 Основні сценарії користувача

### 1. Онбординг і профіль

Під час реєстрації або першого запуску користувач вказує:

- нік
- поточну вагу
- цільову вагу
- бажаний період досягнення цілі
- зріст
- дату народження або вік
- стать
- рівень фізичної активності (седентарний / легка / помірна / висока / дуже висока)

Добова норма калорій повинна розраховуватися автоматично за формулою **Mifflin-St Jeor** з урахуванням рівня активності.

### 2. Ведення щоденника харчування

Користувач може:

- додавати продукти у щоденник за поточний або обраний день
- вносити їжу у текстовому форматі
- обирати продукти зі списку раніше створених
- використовувати швидкі кнопки для додавання з обраного, з попереднього дня або зі збережених сценаріїв
- копіювати прийоми їжі або продукти з попереднього дня з можливістю редагування
- переглядати денний підсумок по калоріях, а також по білках, жирах і вуглеводах

### 3. Категорії прийомів їжі

Базово підтримати такі категорії:

- сніданок
- обід
- вечеря
- перекус

Категорії прийомів їжі не є фіксованими. У майбутньому користувач повинен мати можливість створювати власні категорії. Водночас категорії не повинні бути обов'язковими. Користувач може вести записи як у межах категорій, так і одним суцільним списком за день.

### 4. Перегляд статистики

Користувач може переглядати:

- статистику за день
- порівняння з попереднім днем
- тижневу статистику
- місячну статистику
- графіки у chart-форматі
- окремі значення калорій, білків, жирів і вуглеводів
- історію зміни ваги
- прогрес до цільової ваги

### 5. Навігація по датах

Необхідно реалізувати:

- швидкий перехід між днями
- окремий розділ або режим календаря
- відмітки у календарі, які показують, чи є записи за конкретний день

### 6. Робота з довідником продуктів

Користувач може:

- створювати власний список продуктів
- завантажувати фото продукту
- вказувати назву продукту
- вказувати виробника
- редагувати вручну дані про продукт
- вказувати порцію у грамах/мл або в штуках (наприклад, 2 яйця)

Характеристики продукту повинні генеруватися на основі фото продукту. Для генерації використовуються хмарні мовні моделі через Ollama або Groq.

Ручна модерація перед збереженням згенерованих даних не є обов'язковою. Водночас користувач повинен мати можливість вручну відредагувати будь-які поля після створення продукту.

### 7. Пошук продуктів

Пошук створених продуктів має відбуватися за:

- назвою продукту
- виробником
- штрихкодом

### 8. Нагадування

Користувач може налаштувати push-сповіщення з текстом на кшталт:

- внести продукти, які були спожиті на обід
- внести продукти, які були спожиті протягом дня

### 9. Водний баланс (V2)

Користувач може відстежувати добове споживання води:

- додавати записи в мл
- переглядати прогрес до добової норми
- налаштовувати власну норму або використовувати автоматичну (з урахуванням ваги)

## 🔒 Вимоги безпеки

### Автентифікація та авторизація

- JWT-авторизація з короткоживучим access token (15–30 хв)
- refresh token зберігається виключно в httpOnly cookie (не в localStorage)
- всі API-ендпоінти перевіряють токен і повертають тільки дані поточного користувача (row-level security)
- при розширенні до багатокористувацького режиму — явна перевірка прав доступу на рівні сервера

### Завантаження файлів (фото продуктів)

- обмеження розміру файлу на сервері: max 5 MB
- перевірка MIME-типу файлу на сервері (не довіряти значенню від клієнта)
- оригінальне фото не зберігається на сервері без явної потреби — достатньо результату AI-генерації або стисненої версії

### Rate limiting

- обмеження кількості запитів на ендпоінти: реєстрація, логін, AI-генерація
- захист від brute force атак та зловживання AI API

### Валідація даних

- всі числові поля (калорії, вага, БЖВ, порція) мають серверну валідацію діапазонів
- неприпустимі значення (наприклад, від'ємні калорії, нульова вага) не повинні проходити валідацію

### Управління даними

- endpoint для видалення акаунта з повним каскадним видаленням усіх даних користувача
- посилання на експорт файлів — підписані або одноразові (signed URL)

### Заголовки безпеки

- встановити Content Security Policy (CSP) з явним переліком дозволених зовнішніх джерел (Groq API, CDN тощо)
- встановити стандартні заголовки: X-Content-Type-Options, X-Frame-Options, Strict-Transport-Security

## 📊 Варіанти відображення даних калорій протягом дня

### Варіант 1. Денна шкала прогресу

- загальна кількість спожитих калорій за день
- ціль на день
- прогрес-бар із відсотком виконання
- окремі блоки по категоріях прийомів їжі

### Варіант 2. Таймлайн дня

- прийоми їжі у хронологічному порядку
- калорійність кожного запису
- підсумок за день зверху або знизу

### Варіант 3. Картки по категоріях

- окремі картки для сніданку, обіду, вечері та перекусів
- всередині кожної картки список продуктів і сума калорій
- у верхній частині екрана загальний денний баланс

### Варіант 4. Комбінований дашборд

- зверху денний підсумок
- нижче графік по днях
- нижче список або картки прийомів їжі
